Архитектура msagent

MindStudio Agent — CLI-платформа доменных AI-агентов для отладки и оптимизации на Ascend NPU. Отчёт описывает реализацию, жизненный цикл запроса, точки входа, взаимодействие с LLM и механизмы расширения.

версия 26.1.0-alpha.2 ветка master @ d20e22c Python ≥ 3.11 deepagents 0.6.12 langchain 1.3.x · langgraph 1.2.x дата анализа 2026-08-31

1 Общая реализация

Технологическая основа, слои системы и распределение ответственности по модулям.

msagent представляет собой тонкую специализированную обвязку над стеком LangChain: ядро агентного цикла (вызов LLM → вызовы инструментов → повтор) не реализовано в проекте самостоятельно, а предоставляется библиотекой deepagents, которая компилирует агент в граф LangGraph (CompiledStateGraph). Проект добавляет к этому ядру: декларативную конфигурационную систему (Pydantic + YAML/JSON с версионированием и миграциями), фабрики сборки (LLM, инструменты, скиллы, MCP, агенты), собственные middleware, интерактивный CLI (prompt-toolkit + rich), персистентность состояния (SQLite-чекпоинты), управление контекстным окном (суммаризация с выгрузкой) и аудит.

1.2 Определяющее проектное решение

Доменные агенты (Profiler, Accuracy, Quantizer, Modeling, Operator, Minos) не имеют программного кода — каждый является YAML-файлом с набором Markdown-промптов. Различия между агентами исчерпываются: системным промптом, фильтрами инструментов (tools.patterns), фильтрами скиллов (skills.patterns), перечнем сабагентов и политиками (сжатие, ретраи, чекпоинтер). Экспертиза домена вынесена в промпты и скиллы; код остаётся универсальным.

3 Жизненный цикл запроса

От нажатия Enter до ответа: две фазы — однократная сборка графа и обработка каждого сообщения.

3.1 Фаза A — сборка графа (при старте сессии)

  1. Session.start() → initializer.get_graph()
    Контекстный менеджер над Initializer.create_graph(agent, model, working_dir); по завершении закрывает MCP-клиент и чекпоинтер.
  2. Загрузка конфигурации — ConfigRegistry
    Параллельно (asyncio.gather) читаются агент, LLM и MCP. Каждый вид конфигурации — наложение: пакетные дефолты из wheel (resources/configs/default) + пользовательские переопределения из ~/.msagent/config с пофайловой миграцией версий и field-level overlay по model_fields_set.
  3. Политика одобрений → interrupt_on
    config.approval.json преобразуется в payload для HumanInTheLoopMiddleware; по умолчанию прерывание объявлено только для инструмента execute.
  4. Чекпоинтер
    AsyncSqliteSaver над ~/.msagent/state/projects/<id>/checkpoints.sqlite (либо InMemorySaver).
  5. MCP-клиент
    MCPClient.tools() строит подключения (stdio/sse/http/websocket) и грузит инструменты через MultiServerMCPClient с префиксацией имён <server>__<tool>; применяются include/exclude и обёртка таймаута invoke_timeout.
  6. Скиллы
    SkillFactory.load_skills сканирует SKILL.md в <cwd>/skills → ~/.msagent/skills → встроенный каталог (первый выигрывает), затем фильтр по skills.patterns агента (категория:имя, fnmatch, префикс ! — исключение).
  7. AgentFactory.create() → create_deep_agent()
    Монки-патчи промптов deepagents и Windows-путей; создание модели через LLMFactory; каталог runtime-инструментов + MCP-инструменты; фильтрация по tools.patterns (категория:модуль:имя); бекенд LocalShellBackend/CompositeBackend; middleware-стек; спецификации сабагентов; компиляция в CompiledStateGraph.

3.2 Фаза B — обработка каждого сообщения

  1. Ввод — InteractivePrompt.get_input()
    prompt-toolkit: автодополнение, горячие клавиши (Shift+Tab — цикл режима одобрений, переключатель bash-режима), ссылки @файл/@изображение.
  2. Маршрутизация в Session._main_loop()
    bash-режим → BashDispatcher; префикс / → CommandDispatcher (включая ярлыки скиллов /<имя-скилла> задача); иначе → MessageDispatcher.dispatch().
  3. Построение сообщения
    MessageContentBuilder.build() разбирает ссылки @:file:…/@:image:…/упоминания, формирует мультимодальные content-блоки → HumanMessage. Отдельно собирается AgentContext: рабочая директория, платформа, дата, снимок окружения (git-ветка, языки, доступные утилиты), список MCP-серверов, память проекта, каталоги инструментов и скиллов.
  4. Запуск графа
    graph.astream({"messages": [msg]}, RunnableConfig(thread_id, recursion_limit), context=AgentContext, stream_mode=["messages","updates"], subgraphs=True). Чекпоинтер восстанавливает историю треда по thread_id.
  5. Агентный цикл внутри графа
    Хуки wrap_model_call (подстановка шаблонных переменных в системный промпт, фильтрация инструментов, prompt-caching) → вызов LLM → при наличии tool_calls хуки wrap_tool_call (ретраи, вытеснение крупных результатов, HITL-перехват) → исполнение инструментов (ФС/шелл deepagents, каталожные, MCP, task для сабагентов) → ToolMessage → повтор до ответа без вызовов инструментов.
  6. Потоковый рендеринг и HITL
    Канал messages — токен-превью и индикаторы активных инструментов; канал updates — финальные сообщения (склейка чанков, отложенные заголовки инструментов, учёт токенов, аудит). Ключ __interrupt__ → InterruptHandler: авторазрешение по decision_rules либо диалог approve/reject/always_*; ответ возвращается как Command(resume={interrupt_id: …}), и поток продолжается.
  7. Завершение хода
    Чекпоинт сохранён; счётчики токенов обновлены; при input_tokens / context_window ≥ порога выполняется авто-компакция: суммаризация старых сообщений вспомогательным LLM-вызовом и выгрузка оригиналов в /conversation_history/<thread>.md, затем graph.aupdate_state(_summarization_event).

4 Взаимодействие с LLM

Единственный канал — абстракции LangChain; прямых вызовов провайдерских SDK в проекте нет.

4.1 Конфигурация и создание клиента

Модель описывается LLMConfig (провайдер, модель, alias, api_key_env, base_url, лимиты, температура, таймаут, context_window, произвольные params). LLMFactory.create() нормализует провайдера (openai | anthropic | google/gemini → google_genai) и вызывает init_chat_model("провайдер:модель", …). Ключ API разрешается по цепочке: api_key_env → стандартная переменная провайдера → LLMSettings.

4.2 Особенности OpenAI-совместимого контура

  • Responses API включается только для хостов *.openai.com; произвольный base_url (DeepSeek, vLLM, локальные шлюзы) работает через Chat Completions;
  • stream_usage=true — метрики токенов заполняются и в потоковом режиме;
  • патч patch_chat_openai_reasoning_content_support — поддержка поля reasoning_content «думающих» моделей;
  • при нестандартных http2 / trust_env / verify создаются явные клиенты httpx.Client/AsyncClient.

4.3 Надёжность и места вызова

4.4 Сборка системного промпта

Порядок: (1) конкатенация Markdown-файлов из поля prompt агента; (2) гарантированный блок <local-context>; (3) deepagents дописывает базовый промпт (заменён компактной версией через patch_third_party_prompt_defaults) и секции middleware — инструкции ФС, todo, task, отфильтрованный список скиллов, память; (4) на каждом вызове модели _SystemMessageMiddleware подставляет шаблонные переменные {working_dir}, {platform}, {current_date_time_zoned}, {local_environment_context}, {mcp_servers}, {user_memory} из AgentContext.template_vars (неизвестные плейсхолдеры сохраняются).

6 Дополнительные наблюдения

Сведения, существенные для планирования доработок.

6.1 Конфигурационная система

  • Двухуровневое наложение: дефолты читаются напрямую из wheel и не копируются; пользовательский файл может содержать только изменяемые поля — _overlay_model накладывает по model_fields_set, остальное наследуется. Обновления пакета не конфликтуют с пользовательскими правками.
  • Версионирование: каждый конфиг несёт version; VersionedConfig.migrate() содержит пошаговые миграции, файлы перезаписываются атомарно.
  • Изоляция проектов: состояние — в ~/.msagent/state/projects/<slug>-<sha256[:12]>/ (чекпоинты, память, история диалогов, аудит); рабочая директория кода не засоряется.

6.2 Управление контекстным окном

  • tools.output_max_tokens — результат инструмента сверх лимита вытесняется в виртуальную ФС (/large_tool_results/), в контексте остаётся ссылка;
  • авто-компакция по порогу 0.8 и ручная /offload: суммаризация + выгрузка оригиналов в /conversation_history/<thread>.md с возможностью последующего чтения агентом;
  • каталожные инструменты fetch_tools/get_tool/run_tool позволяют держать в схеме LLM минимум инструментов, вызывая остальные по имени.

6.3 Зафиксированные несоответствия и риски

Требует внимания при доработке
  • Приватные API deepagents: оффлоад (utils/offload.py) вызывает SummarizationMiddleware._acreate_summary, _filter_summary_messages и др.; монки-патчи промптов и validate_path глобальны для процесса. Обновление deepagents/langchain — операция повышенного риска; фиксация версий в pyproject.toml обоснована.
  • verify=False по умолчанию в LLMConfig: для OpenAI-совместимого контура всегда создаются httpx-клиенты с отключённой проверкой TLS-сертификата. Для публичных эндпоинтов рекомендуется явно устанавливать verify: true.
  • Декларированные, но не задействованные элементы: use_catalog читается, но не используется фабрикой; ApprovalMode (semi-active/active/aggressive) влияет только на индикацию CLI — фактическое управление одобрениями выполняют interrupt_on/decision_rules; middlewares/approval.py — заглушка; SandboxConfig и профили sandboxes/*.yml загружаются, однако sandbox_bindings в фабриках отбрасываются (зарезервировано).
  • Синглтоны и неявные контракты: модульный initializer с кэшами; служебные атрибуты _llm_tools, _agent_backend навешиваются на скомпилированный граф для интроспекции CLI.

6.4 Наблюдаемость и тестируемость

  • Аудит: JSONL-события user.turn, user.response, делегирования сабагентам (с валидацией типизированных IO-конвертов) — включается audit_log.enabled в YAML агента;
  • Трассировка: --trace-jsonl пишет полный протокол прогона (CliRunRecorder);
  • Тестовые двойники: FakeGraph + MSAGENT_FAKE_BACKEND=1 позволяют выполнять e2e-тесты CLI без LLM; каталог tests/, маркер integration.

6.5 Рекомендуемая последовательность освоения

  1. cli/bootstrap/app.py → legacy.py → chat.py — маршрутизация запуска;
  2. cli/bootstrap/initializer.py — сборка всех зависимостей;
  3. agents/factory.py — центральный узел: инструменты, middleware, сабагенты, компиляция графа;
  4. cli/dispatchers/messages.py — потоковая обработка и прерывания;
  5. resources/configs/default/ — образцы декларативных определений;
  6. документация: docs/zh/developer_guide/arch_overview.md, add-agent.md, docs/zh/user_guide/configuration-and-extension.md.
