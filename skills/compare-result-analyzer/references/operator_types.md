# 算子类型修正参考

> **用途**: 本文件定义 compare-result-analyzer skill 的「算子类型修正」规则——哪些算子在精度分析中需要特殊处理，分析步骤 5（算子类型修正）时，agent 必须先 Read 本文件。规则分两类：
> 1. **豁免算子**（empty* / numpy / to）：天然不执行数值计算，NRE 不反映实现差异，即便超阈值也不作为根因。
> 2. **输入占位算子**（集合通信类）：output 是真实可分析信号，但 input 是占位缓冲、input→output 传播判定无意义，只能用 output 做上下游分析、作为传播边界处理。
>
> 这两类规则与 `references/thresholds.md` 的阈值判定配合：即便某算子 NRE 超过阈值，若属本文件列明的特殊类型，应按对应规则降级或边界处理。

---

## 核心原则

精度问题定位的是**计算逻辑不一致**——CPU 与 NPU 对同一输入算出不同结果。但有两类算子不能套用"input→output 跳变"的标准传播判定：

- **无计算算子**（empty* / numpy / to）：根本不执行数值计算，输出与输入逐元素相同或是未初始化内存残留，NRE 不反映实现差异，**豁免、不作为根因**。
- **集合通信算子**：输出由跨 rank 数据组装/规约而来，本 rank input 仅是发送缓冲占位，input→output 无逐元素对应关系，**输入侧豁免**，但 output 仍是真实信号，**仅用 output 做上下游分析、作为传播边界**。

**通用判定**：以下算子即便 NRE 超阈值，也应按对应规则降级处理（豁免或边界），**不直接作为根因**。确认根因须沿执行序找到真正做计算、且 input→output 关系成立的算子。

---

## 类别 1：豁免算子清单（不作为根因）

### 1. 未初始化内存分配类（empty* 族）

| 算子 | 说明 |
|---|---|
| `empty` | 分配未初始化内存的张量 |
| `empty_like` | 按参照张量 shape/dtype 分配未初始化内存 |
| `empty_strided` | 按 stride 分配未初始化内存 |
| `empty_with_format` | 按指定内存格式分配未初始化内存 |
| `new_empty` | 在已有张量上分配未初始化内存（Tensor 方法） |
| `new_empty_strided` | 在已有张量上按 stride 分配未初始化内存 |

**为什么不会有精度问题**：这类算子的输出是**未写入任何值**的内存区域，内容是底层内存的非确定残留（"垃圾值"）。bench 侧与 NPU 侧各自拿到的是两段不同的未初始化内存，比对出的 NRE 仅反映两段垃圾值的差异，**与算子实现、与精度完全无关**。即使 NRE 极大（甚至接近 100%），也不构成精度问题证据。

**分析动作**：
- 标注为「未初始化内存分配——输出为非确定残留，NRE 无意义」，不进入首问题点候选、不进入 ROOT_CAUSE。
- 这类算子是"占位算子"，真正写入值的计算发生在**后续覆盖该内存的算子**（如 `copy_`、`fill_`、in-place op 或 kernel）处——沿执行序向后找覆盖写算子作为实际承载计算的位置。
- 与 `references/constraints.md` C-ANALYSIS-001（不可忽略判定）的关系：empty* 族不适用 NRE 不可忽略判定，即便 NRE 超阈值也豁免。

### 2. 跨后端视图/转换类（numpy）

| 算子 | 说明 |
|---|---|
| `numpy` | `Tensor.numpy()`，将张量转为 NumPy 数组（CPU 视图，通常不复制值） |

**为什么不会有精度问题**：`numpy()` 是零拷贝视图转换（连续内存时）或纯搬运，不做任何数值计算。输出与输入逐元素相同。任何 NRE 必然**继承自输入张量本身已有的误差**。

**分析动作**：按 INPUT_PROPAGATION（误差继承自输入）处理，误差来源向上游溯源（C-ANALYSIS-008），`numpy` 节点本身仅做说明。

### 3. dtype/设备搬运类（to）

| 算子 | 说明 |
|---|---|
| `to` | `Tensor.to(dtype, ...)` / `Tensor.to(device, ...)`，dtype 转换或设备搬运 |

**为什么一般不会有精度问题**：
- **同精度搬运 / 升精度**（如 fp32→fp64、跨设备同 dtype）：逐元素不变，NRE 必继承自输入。
- **降精度转换**（如 fp32→bf16/fp16）：存在表示性舍入（rounding），但这是**定义良好的预期行为**，不是实现 bug。其舍入误差量级受 dtype 精度边界约束（参见 `references/thresholds.md` 的 dtype 精度边界），通常会被近零噪声过滤或处于阈值量级内。

**分析动作**：
- 同精度/升精度 → INPUT_PROPAGATION，向上游溯源。
- 降精度转换 → 若 NRE 处于 dtype 精度边界量级，按「预期舍入」仅做说明；若明显超出该量级，再结合上游输入交叉核对（误差仍可能继承自上游）。
- **verify 语义边界**（与 §8 一致）：`to` 这类算子即使 verify_op 通过也仅证明实现一致，**不排除"此处决定降精度"本身就是整网误差的设计性根因**。verify 通过 ≠ 根因排除，需结合上游计算链与网络精度策略综合判断。

## 类别 2：输入占位算子（仅用输出做上下游分析）

与上一节"豁免算子"不同，这类算子的**输出是真实可分析的信号**——它的 NRE 反映跨 rank 聚合/规约后的真实误差，并非无意义。豁免的只是**输入侧**：input 是本 rank 的发送缓冲占位，output 由**其它 rank 的数据**组装/规约而来，与本 rank 的 input 没有逐元素对应关系。因此 input→output 的传播判定无意义，**禁止用 input 去判该算子的传播分类**，只能用 output 做上下游分析。

### 算子清单

| 算子 | 语义 | 为什么 input→output 无意义 |
|---|---|---|
| `_reduce_scatter_base` | 跨 rank 规约后分片 | input 是本 rank 待规约的完整张量，output 是规约后落到本 rank 的分片——output 依赖所有 rank 的 input，非本 rank input 单独推导 |
| `_all_gather_base` | 跨 rank 全收集 | input 是本 rank 局部分片，output 是所有 rank 拼接的完整张量——output 尺寸远大于 input，非逐元素派生 |
| `all_to_all_single` | 跨 rank 重排 | input/output 在 rank 间重排切片，本 rank 的 input 与 output 无逐元素对应 |
| `batch_isend_irecv` | 批量发送/接收 | input 是发送张量列表，output 是从其它 rank 接收的张量——发送与接收分属不同 rank，无对应关系 |

**共性**：output 由跨 rank 数据组装/规约而来，本 rank input 仅是发送缓冲占位。input→output 的 NRE 跳变（C-ANALYSIS-003 四种模式）、多 input 复合优先级（C-ANALYSIS-014）、input 误差继承判定（C-ANALYSIS-002 step 2 / C-ANALYSIS-004）**均不适用**。

### 分析动作（关键）

这类算子的 input→output 关系不成立，但 **output 是真实可分析的信号**——按 output 判定，该算子**可作为根因候选/首问题点**。处理方式：

1. **输入侧豁免**：跳过 input→output jump 与基于 input 的标签（INPUT_PROPAGATION / 基于 input 干净的 PASS_THROUGH 等）。C-ANALYSIS-002 step2（input 继承检查）、C-ANALYSIS-003（input→output 四模式）、C-ANALYSIS-004（多 input）、C-ANALYSIS-014（多 input 复合优先级）的 input 侧**均不适用**。
2. **仅用 output 判定**：output NRE 是有效信号，按 output 判定 C-ANALYSIS-001（不可忽略）→ 该算子**可作为根因候选/首问题点**。下游吸收检查（C-ANALYSIS-007）与下游传播照常用 output 进行——即 output→下游算子的边正常分析。
3. **上游溯源到此为止**（C-ANALYSIS-008）：上游追溯遇到这类算子即停止——本算子的 input 是占位缓冲，真正的上游是**其它 rank**，超出本地 dump 的执行图范围。标注 `trace_boundary_reason` = "集合通信算子输入为占位缓冲，上游跨 rank，超出本地执行图"。
4. **跨 rank 源提示**：因上游跨 rank，该算子被列为候选/首点时存在两种可能——(a) 本算子集合通信实现有 bug（需多卡环境 verify 确认，见下节）；(b) 对端 rank 发送了脏数据，本算子只是边界入口。**建议结合跨卡共识分析**（§3.6 / `references/multi_card_rules.md` M-002 跨卡共识根因）定位对端 rank 交叉确认，避免误把中继当根因。
5. **跨卡关联**：这类算子天然是多卡误差在单卡 dump 上的投影——output 脏往往意味着**某个对端 rank 发送了脏数据**。结合多卡报告的「跨卡共识根因」「卡特定根因」交叉定位对端 rank。

### 与 verify 的关系

这些算子多为集合通信实现，verify_op.py 通常无法在单卡环境重建（依赖多 rank 进程组）。验证报告中按 §8「验证受限说明」标注"集合通信算子，单卡环境无法重建"即可，不作为验证通过/失败的依据。

## 报告呈现约束

- **豁免算子**（empty* / numpy / to）：**不进入**报告 §3 候选表 / §5.1 根因候选 / §5.1a 显著放大算子。
- **输入占位算子**（集合通信类）：output 行按 output NRE **可作为根因候选/首点**正常出现在传播链中，但须标注「集合通信中继/边界——输入为占位缓冲、上游跨 rank、仅用 output 判定，建议跨卡共识（M-002）交叉确认」。
- 在报告 §7 元信息异常节或算子类型修正说明中，**集中列出**被豁免/边界处理的算子及理由（"未初始化内存分配，NRE 无意义" / "视图转换，误差继承自输入" / "dtype 搬运，预期舍入" / "集合通信中继，上游跨 rank"），让用户知道这些节点已被识别并特殊处理。
- 术语遵循 `SKILL.md` 报告可读性约束：用「误差继承（源自输入）」「占位算子」「集合通信中继」等通用表达，不出现 JSON 字段名或约束编号。
